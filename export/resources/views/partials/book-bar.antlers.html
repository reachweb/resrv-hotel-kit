It hides while any booking UI marked `data-hides-book-bar` is on screen (the home search card, a detail page's panel, the rooms sticky search, a CTA band's button), so it never doubles or competes with what's already in view — the `bookBar` component in site.js. The footer grows by the bar's height wherever the bar can show, so the bar never covers its last line. Params: href, label, price, price_label (default "from"), unit, until — sm (default: the header shows Book Now from sm up) | lg (pages whose booking panel only becomes sticky from lg). Short viewports (a phone on its side) skip it: with the header it would take a third of the screen. A same-page link (#book, #reserve, #treatments) also moves focus to its target (`follow` in the bookBar component), so a keyboard or screen-reader user carries on from the booking rather than from the top of the page. Give the target tabindex="-1" and focus:outline-none: it is a container, not a control, so it takes no ring. #}} {{ if href }}
